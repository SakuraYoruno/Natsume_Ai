# 历史归档（docs/_history/）

本目录用于存放被新版文档替换、不再代表当前代码事实的历史快照。所有文件保留原内容，仅做归档，便于追溯。

## 归档原则

- 一旦核心事实文档（如 `CURRENT_CODE_ARCHITECTURE.md`）被重写，旧版按"版本号_日期"格式归档到本目录的对应快照子目录。
- 历史方案、阶段性 audit、旧的封板报告**不**强制迁入此目录；它们仍然按原路径保留在 `docs/35_quality/audits/`、`docs/50_release/`、`docs/60_trace/` 下，作为追溯链的一部分。
- 仅当某份文档被显式判定"已过期 / 与当前代码强冲突 / 不应再被读"时，才迁入此目录。

## 当前快照子目录

- `2026-04-22_arch_snapshot/` — 2026-04-22 时点的"当前代码架构"快照，对应 `README.md` 重写之前的状态。在 2026-05-30 文档全量重写时被替换。

## 写作约定

每个快照子目录建议放一份 `INDEX.md` 说明：
- 这次归档是哪份新文档把它替换掉了
- 归档原因（架构变更 / 模块拆分 / 入口迁移等）
- 归档时间与对应 git commit
