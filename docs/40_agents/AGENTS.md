# Natsume AI 仓库协作规范

## 产品优先级

项目核心是七海的实时情感陪伴。普通聊天优先自然度和延迟；只有工具、设备、外部写入和高风险动作使用完整治理链。不要为了形式上的严谨把每轮对话重构成重型审计任务。

## 修改原则

- 先读生产调用点，再改合同或抽象。
- 保持用户 affect 与七海 self affect 隔离。
- `Soul.md` 核心人格不得由在线学习改写。
- 保持 canonical Life journal 的情感与关系 authority。
- Edge 位于另一台电脑，未经用户明确允许不得启动。
- 不提交密钥、模型、语料、用户数据、原始音视频或运行日志。
- 不删除 migration 和审计证据；退出当前 authority 的材料移入 `docs/_history/`。

## 交付

- 分支使用 `codex/` 前缀，基于最新 `dev`。
- 提交、PR 标题和正文使用中文。
- 每个代码提交同步受影响文档和机器状态并立即推送。
- 小切片运行定向测试；波次只集中运行一次集成；真实服务栈在验收阶段启动。
- GitHub Actions 因额度没有执行时记为 `NOT_RUN_ACCOUNT_QUOTA`。
- PR 正文包含目标、生产接线、旧路径、本地验证、远程 CI、边界和回滚。

## 状态

`WIRED`、`LOCAL_PASS`、`PARTIAL` 和历史 receipt 都不等于最终 `PASS`。完成结论必须与生产接线、目标环境和当前机器状态一致。
