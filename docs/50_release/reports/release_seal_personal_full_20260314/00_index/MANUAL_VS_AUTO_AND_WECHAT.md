## 二、微信（F-24 / F-40）尚未实测，含「监听微信消息」

**结论**：**微信链路目前没有做过真实环境实测**；封测计划中的「wechat callback → host dispatch → reply → egress」和「监听微信消息」都依赖你本机环境。

### 2.1 真实实测需要你做的

1. **监听微信消息**  
   - Edge 端需运行 **微信监听**：`edge_client/channels/wechat_listener.py`，配合本地 Hook 工具（如 WeChatFerry/wcf）把微信收到的消息 POST 到 Edge 或 Host。  
   - 即：本机微信（小号）登录 → Hook 工具抓消息 → 转发到 `POST /v1/host/input`（source=WECHAT）或 Edge 再转 Host。  
   - 这一步 **必须在你本机配置并运行**，无法由别人代测。

2. **完整链路**  
   - 微信收到一条消息 → 监听上报 → Host 处理 → 回复 egress 回微信。  
   - 你需要在本机确认：消息不丢、去重有效、回复在微信里可见。

### 2.2 若暂不启用真实微信，可先做「模拟实测」

不登录微信、不跑监听也可以先验证 **Host 侧 WeChat 通道与主链路**：

1. **检查是否已配置**  
   - `GET /obs/wechat/stats`（若存在）看 WeChat 通道状态。

2. **模拟 WeChat 入站**  
   - 直接调用 Host：  
     `POST /v1/host/input`  
     body：`{"source": "WECHAT", "message": "你好", "from_wxid": "wxid_test", "to_wxid": "wxid_bot", "msg_id": "msg_001", "content": "你好"}`（字段以实际 API 为准）。  
   - 检查：主链路有对应 `request_id`、有回复、`channel_io_log` 有 ingress/egress。

3. **模拟重复消息**  
   - 同一 `msg_id` 再发一次，应被去重（第二次无新请求或标记为 DUPLICATE_IGNORED）。

这样可以得到：**F-24/F-40 在「无真实微信、无监听」下的 N/A 结论**，或 **「模拟 WeChat 输入」下的通过结论**；真实「监听微信消息→回复」需你本机接通监听后再测一次。
